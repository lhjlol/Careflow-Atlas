# Architecture

## System shape

```text
synthetic XLSX / fixture
        |
        v
workbook adapter + validation
        |
        v
provisional domain snapshot
        |
        v
repository + localStorage adapter
        |
        v
Zustand workspace store
        |
        +------> React workflow panels
        |
        +------> map view model ------> MapLibre renderer
```

The application is client-side React 19 and TypeScript, built with Vite 6. Zustand owns the shared workspace selection and imported snapshot. Components do not embed fixture-specific records.

## Domain and temporal semantics

[src/domain/types.ts](../src/domain/types.ts) separates buildings, floors, units, people, households, household membership, residence, membership, visits, and observations. These types are provisional because the NGO's real forms have not been supplied.

Coverage, contact outcome, housing assessment, source, and follow-up are independent fields. A blank coverage import becomes `UNKNOWN`; it does not become `UNVISITED` or `VISITED_NO_FINDING`. Derived building/floor summaries respect scope so a single unit event cannot declare an entire building complete. Unknown totals remain unknown and do not produce a percentage.

Observations carry occurrence and recording timestamps. Derived state uses occurrence time first and recording time to break ties; a stale building or floor event cannot override newer unit work. Counts describe distinct recorded locations rather than event volume. Saving appends an immutable event. A repeated event ID is accepted only when its content is identical; a conflicting reuse is rejected. Current correction semantics are append-only rather than in-place editing.

## Import and persistence

[src/data/workbookImport.ts](../src/data/workbookImport.ts) parses `.xlsx` bytes with SheetJS. It accepts only the deliberately designed synthetic workbook contract, requires synthetic metadata, validates headers, values, dates, IDs, and entity relationships, and returns no snapshot when errors exist. Unknown sheets and blank coverage produce visible review messages.

The workbook is an import shape, not the future NGO schema. [scripts/generate-demo.ts](../scripts/generate-demo.ts) generates the bundled sample from the domain fixture.

[src/data/repository.ts](../src/data/repository.ts) is the data-access boundary used by the UI. Its `PersistenceAdapter` currently uses browser `localStorage`. [src/domain/schema.ts](../src/domain/schema.ts) uses Zod to validate every collection, calendar and instant fields, duplicate IDs, parent chains, and follow-up resolution references before a snapshot is read or written. A future remote repository can replace the adapter without moving storage logic into components.

Import deliberately replaces the current synthetic snapshot after a visible review step. The UI caps selected workbook files at 5 MB. Export produces a complete synthetic JSON snapshot with history.

## Map and selected building

[src/map/MapScene.tsx](../src/map/MapScene.tsx) uses MapLibre GL JS 5.24. OpenFreeMap Positron supplies the real OSM-based basemap and surrounding building extrusions when available.

The selected-building layer is independent GeoJSON generated by [src/map/mapModel.ts](../src/map/mapModel.ts). MapLibre renders both target buildings and separated floors with native `fill-extrusion`. Floor base/height animation and picking therefore share the same camera and renderer. The map renderer receives only spatial IDs and summaries; people and observation notes do not enter the map model.

Target footprints, heights, floors, and units are synthetic and illustrative. Selecting a target triggers a controlled camera transition. Expanding floors animates the vertical gaps and keeps the building at its mapped location. Reduced-motion preferences disable the long camera and floor animations.

If the map style or WebGL fails, the list, building detail, history, and record form remain usable. Selecting an unsupported context building produces a clear no-demo-records message.

## Implemented boundaries

The repository has seams for workbook import, persistence, and map presentation. It does not implement a backend, production database, authentication, RBAC, tenancy, offline sync, audit service, government-data integration, real Excel migration, or real approval workflow.

Production work must add an authenticated server-side data boundary before any real person, household, phone, address, membership, or outreach history is stored. It must also define conflict handling, audit, retention, deletion, backup, permissions, and provider governance with the NGO.

## Spatial focus and operating limits

Floor labels are projected from each slab’s geographic coordinate and altitude through MapLibre’s current view matrix. During focus, loaded OSM multipolygons are split into individual footprints and nearby overlapping context is masked so it cannot hide the illustrative stack. This is a presentation treatment, not a corrected survey or authoritative building model. Other context remains visible and returns to the normal layer in overview.

Map and workbook bundles load on demand. The map remains an optional network/WebGL dependency; local records are not an offline tile cache. The optional WebMCP surface exposes synthetic coverage summaries and validated building navigation, with record creation and import still handled through the visible UI.
